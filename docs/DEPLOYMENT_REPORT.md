## HTTPS и общий nginx

Certbot klaster-key выпустил один сертификат на оба домена. Email:
`parsec@toolzar.ru`; срок до **09.02.2027**. Сертификаты находятся в существующем
`/opt/klaster-key/deploy/certbot/conf/live/parsec.toolzar.ru/`.
Имеющийся cron `/etc/cron.d/klaster-key-certbot` запускает `renew_cert.sh`
дважды в день и подхватывает новый сертификат; cron не менялся.
Тест `certbot renew --cert-name parsec.toolzar.ru --dry-run` завершился успешно
для обоих доменов. Проверка затрагивала только новый сертификат.

В `/opt/klaster-key/deploy/nginx-tls.conf` дописаны только блоки Parsec.
Исходные байты сохранены; nginx прошёл `-t` и reload без рестарта.
На сервере до работ уже был устаревший bind mount: контейнер держал удалённый
inode конфигурации от 09.10.2026. Его содержимое совпадало с исходным файлом
до нашего append. Для сохранения контейнера mount ровно этого файла временно
переведён в rw через его mount/PID namespace; в него дописан тот же фрагмент,
затем mount немедленно возвращён в ro. Фактический конфиг контейнера и хостовый
файл побайтово совпадают. Nginx не перезапускался.

**Передать Семёну [готовый патч](../infra/nginx/klaster-key-parsec.patch), чтобы он
закоммитил его в репозитории klaster-key.** Сейчас изменение применено на сервере,
но его `git reset --hard` перезапишет хостовый файл. Патч создан от исходного
серверного конфига, не содержит секретов. Полный конфиг в Git Parsec не включён.
Копии исходного, фактического mounted-конфига и патча лежат в серверных backups.
На действующем сервере патч повторно не применять: изменение уже внесено.
В чистой копии klaster-key сначала `git apply --check klaster-key-parsec.patch`,
затем `git apply klaster-key-parsec.patch` и обычный коммит Семёна.

```bash

```

Deploy-скрипт также делает fast-forward pull и обновляет только backend/frontend
с `--no-deps`; БД/Redis не пересоздаёт. Для общего сервера сборку при следующих
обновлениях планировать с учётом нагрузки; первый раз сборка выполнена локально.

Снимать `STUB_MODE` запрещено до исправления подписи платёжного webhook.
Публичное API имеет прежнее поведение, кроме согласованной блокировки частот
в заглушке; lint-изменения типов перечислены в принятом lint-отчёте.
`parser-heartbeat` оставлен открытым намеренно; `selectors/report` требует admin.
Подробный список выключенного и порядок восстановления:
[STUB_MODE_RESTORATION.md](STUB_MODE_RESTORATION.md).

Остаётся внешнее действие: Семён должен закоммитить nginx-патч и проверить
доступ к PostgreSQL со своего IP. Персональные DB-пароли публично не выдаются;
использовать согласованный приватный канал или root-env на сервере.
