# Ручной тест после одобренного R3

**Результат: ручной тест подтверждён Nick 11.11.2026, кодовая часть завершена.
Nick разрешил перейти к остальным работам; публикация кода выполняется после
подготовки сервера.** Ниже сохранён выполненный чек-лист и описание стенда.

Внешнее ревью R3 пройдено. Стенд: http://parsec.toolzar.localhost:13020,
API: http://api.parsec.toolzar.localhost:17101. Это отдельная копия дампа,
не рабочий стейдж и не сервер. Открывать в инкогнито: имя и домен cookie те же,
что у старого стейджа, а порты не изолируют cookie.

После одобренной lint-итерации оба новых Docker-образа проверены сборкой,
но текущие контейнеры ручного стенда не заменялись. Они работают на R3;
отличия кандидата на коммит — принятые ревьювером типовые/форматные правки
и настройки lint, без изменения поведения публичного API.

Перед передачей Nick проверены HTTP 200 клиента, health stubMode:true и
аутентификация живого SMTP без отправки письма. Перехват SMTP снят; при ручном
сбросе теперь отправляется настоящее письмо. Лимиты in-memory обнулены после
перезапуска только проверочного backend.

1. Лендинг → «Регистрация». Зарегистрировать новый тестовый адрес, доступный Nick.
   Ожидается автоматический вход и заглушка без меню и кнопок пополнения.
2. Проверить поддержку на лендинге и заглушке: ссылка ведёт на @parsec_help.
3. «Выйти» → вход старой тестовой учёткой из дампа → та же заглушка.
   Прямой переход на /dashboard без сессии должен вести на /login.
4. Проверить «Забыли пароль?» на НОВОЙ тестовой учётке: получить реальное письмо,
   открыть ссылку, задать новый пароль, войти им. Старую учётку не менять.
5. В конце проверить 429: несколько раз подряд отправить неверный пароль в форме
   входа. После суммарных 10 попыток с IP за минуту (включая успешные) должна
   появиться понятная русская ошибка. Перед следующей попыткой подождать минуту.

Сброс ограничен 3/IP в минуту и 3/адрес в час. Не выполнять серию SMTP-тестов
на один адрес. Заявки import-request отправляют настоящую почту на служебный
ящик и не входят в этот ручной чек-лист.

Текущее окружение backend задано ignored tmp/manual.env с живыми SMTP-настройками;
секреты в Git не добавлены. Старые автоматические HTTP-harness из tmp запускать
только после возвращения SMTP-перехвата, иначе они могут отправлять реальные письма.

После результата Nick — отдельная команда на коммит/push, затем на серверный
этап. До этого production-действия не выполнять.
